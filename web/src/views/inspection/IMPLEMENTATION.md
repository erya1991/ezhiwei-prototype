## 数据与状态实现

- 两个专属数据文件提供确定性样本、联合状态与业务操作，没有网络请求。稳定样例包含锅炉房、1/2号锅炉、唯一共用蒸汽管路、压缩空气机房与两台空压机及系统、三间不同楼层配电房、跨楼层空调组合，以及关系缺失机房。
- 内置历史抄表样本固定为 2026-10-28 的 08:00 / 10:00；待执行样本固定为 2026-10-29，并明确标记内置演示样本。1/2号锅炉、不同时间的结果分别保留，不随机换数。
- 本模块使用 `ezhiwei:equipment-inspection:v1:state` 浏览器存储；不可写/容量不足时有可见提示，当前内存仍保留操作。此能力不等于离线同步、后端持久化或多端共享。
- 计划保留一次核对的规则/范围；相关对象资料、关系或条件变化后，未来生成前要求重新展开确认。规则发布新版本保留旧版本；不自动切换既有计划。
- 每张任务复制当时的计划版本、规则、空间、实际对象、检查项、单位与参考条件。后续修改规则、设备状态/位置、停用计划，不回写已生成任务及记录。
- 原始结果以对象、分组、检查项共同标识，保留检查人、实际填写时间、原值、判定、异常说明和本地照片。记录按这些原始结果聚合，无独立的手工台账数据源。
- 执行状态为待执行/进行中/已完成，检查结果为未检查/未见异常/存在异常/未自动判定，时间状态为未超期/已超期/逾期完成，独立计算。完成不自动变正常；无有效参考条件不判正常。
- 提交前可以暂存真实异常读数；必检、合法输入和必要异常说明/照片齐全才允许最终提交；提交后只读。同计划/日期/开始时段禁止重复生成；演示按钮只可生成今天或未来合法日期。

### 实际业务规则

1. **设备历史同源、只读。** 详情查询与记录模块同一 `records()` 派生结果，按实际对象ID关联；不新增持久化历史数组。显示原始值、单位、原结论、异常说明、本地照片、检查人与实际时间。日期范围按实际检查日期计算，结论筛选只作用于当前明细。完整任务视图仍展示整张任务的所有对象，避免把局部结果误称为整任务结论。
2. **组合默认自身。** “包含子设备记录”依据当次任务中的组成快照，保留子设备编号和读数归属；不使用当前改挂关系重写历史。新任务增加组成祖先快照；旧任务保留原有父ID及任务可追溯链，不猜测未保存的多级祖先。
3. **三维关系独立。** 组成仍用 `parentId`，系统仍用 `systemId`，位置仍用 `spaceId`；设施关联继续引用唯一设施ID。组合或系统维护成员时只调整现有对象引用，不重复建档。保存前整体检查自指、组成/系统循环、同项目及适用目标，验证失败不部分保存。普通设备可不选父设备；省略设施修改参数时保留原关联。
4. **分组统一匹配。** 分组配置作用类型、匹配方式及分类ID；型号/工况可选。检查项继承本组条件，保留既有项目特殊条件作为进一步限定。匹配方式为自身、空间内设备、组合成员、系统成员、明确设施；旧 `members` 按根对象兼容解析，不批量改写旧规则。只选类型、分类和关系，不绑定真实设备ID或按名称猜测。
5. **多路径有边界。** 普通场景使用一种匹配方式；需要时可展开补充路径，同组统一过滤和去重。空间关联的系统按其管理空间或该空间中成员已登记的系统引用确定。选中一个系统不会自动扩大到上级系统的其他成员。新建的明确设施组可选择同时查找关联系统的设施；旧规则保持原匹配行为，需编辑为新版才能采用新增条件。
6. **检查位置不能猜测。** 普通设备和仅通过系统找到的设施使用自身安装空间。明确关联到空间的设施可在该空间形成检查点；一段管路明确关联两个空间时分别保存结果，不复制设施档案。仅有系统归属不能凭空把设施搬到当前房间。
7. **去重保留语义。** 同一计划展开内按检查位置、实际对象ID、分组身份、检查项身份去重，并展示路径及合并数量。不同分组、不同计划和不同位置保留独立检查。新任务结果键增加位置上下文；旧任务没有该字段时继续使用原键，不迁移原读数或重算原结论。记录页也保留位置维度。
8. **计划和历史保护。** 继续一次规则→实际范围→自动展开与核对→周期/人员→启用；必需组缺关系、型号/工况不适用等显示具体原因。旧计划的确认指纹与新增展开格式不同，需要重新展开确认后才能继续模拟生成；不自动改规则版本、计划状态或已有任务。一个计划一个时段仍只生成一张任务。

新样例 `rule-boiler-room-daily` 为独立规则，不覆盖原 `rule-boiler-room`。沿用原锅炉分类ID和两台锅炉的稳定ID，房间环境3项、两台锅炉各2项、管路2项，展开为 **4个对象、9项检查**。数值参考仍明确为模拟演示值。对已保存浏览器状态仅增补这条新样例及资料修订标记；同编号或同名冲突时跳过并提示，不覆盖人工维护内容或历史版本。
