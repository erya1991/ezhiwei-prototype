## 2. 入口与使用

在 web/ 使用现有 npm 锁文件：

~~~powershell
npm ci
npm run dev -- --host 127.0.0.1 --port 15175 --strictPort
~~~

先通过原登录界面进入系统。“工单演示账号”模拟具体业务账号，不替代系统登录。本文不记录登录口令。

| 菜单 / 视图 | 路由 | 内容 |
|---|---|---|
| 工单台账 | /work-order/ledger | 组合筛选、分页、人工报修、首派前编辑、问题补充、共用详情及授权动作 |
| 我的工单 | /work-order/mine | 我的待办 / 我发起的 / 我参与的 |
| 工单规则配置 | /work-order/rules | 分类与默认值、派单规则两页签；版本、启停及修改记录 |
| 移动台账 | /work-order/mobile/ledger | 卡片、分组填报、设备 / 空间选择、图片及详情 |
| 移动我的工单 | /work-order/mobile/mine | 同一账号待办与现场反馈、提交、验收及授权管理动作 |

旧 /work-order 跳转台账；详情使用 ?id=<工单ID>。PC、移动端和本人视图使用同一记录及动作层，不复制业务数组。移动端为浏览器响应式演示，未作原生小程序或物理手机验收。

推荐走查：

1. 陈报修创建设备维修，选择 1 号锅炉，确认位置 / 专业带出及默认发起人验收。建单、自动派发结果分别提示。
2. 巡检员甲在“我的待办”接单、反馈，在移动端提交结果并引用本单已有图片。
3. 发起人修改验收为工程验收组，赵验收甲退回；主处理人再次提交，钱验收乙通过。每轮仅一项共享事项。
4. 周调度走查接单前退回、同 / 跨组织转派、协办转主办、调期与终止。待验收不提供转派。
5. 林配置维护分类、时限和规则；切换访客 / 范围外账号检查权限，查看终态只读历史。

## 4. 关键实现

[workOrder.js](../../data/workOrder.js) 提供 createWorkOrderStore，注入时钟、存储和资料入口；浏览器使用单例。页面只查询或调用动作，不直接改状态。

- 动作校验账号、功能权限、院区、状态、关系、版本、派发 / 提交身份；旧窗口被拒时输入保留。
- 工作副本校验完整，持久化成功后发布；实际读写异常和模拟失败不留半单 / 日志。请求 ID 和输入指纹防重复。
- 主单、类别快照、派发、补充、反馈、提交、验收、调期、日志关联保存；业务正文一份，日志引用记录 ID。
- 首派事实永久保留；接单退回不解锁原问题；终态无修改、删除或重开；终止不生成验收成功。
- 同 / 跨组织转派统一流程；协办升主办后移出当前集合，原主办不自动成为协办；反馈保留实际账号。
- 分类支持三种默认验收、三档时限、自验、启停及版本；规则条件 AND、多值 OR，同院区启用顺序唯一。先取首条再校验目标，不静默跳下一条；建单只自动尝试一次。
- 首派前换类别采用新版本，明确优先级 / 手工验收保留；仅改优先级使用已采用版本。恢复默认为明确动作；首派后调整优先级不重算期限。
- 每次派发独立接单期限；首次有效派发确定处理期限；每次提交独立验收期限。提交固化当时截止与及时性，延期不回写；最终及时性取验收通过对应提交。
- 人员 / 角色对象互斥，角色一人有效结论结束当轮。派发按拟处理人预检自验，提交 / 验收按实际提交者复核。
- PNG / JPEG / WebP，每次最多 3 张、每张 1 MB，读取后验证可解码；可移除未提交图片、预览、引用已有证据，保留稳定 ID 和原提交者。
- 隐患样例显示“隐患转入（占位）”及 HZ-DEMO-001，初始待人工派发；无自动转单、销号或巡检回写。
