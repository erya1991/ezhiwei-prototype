# 跨模块协议预留（待确认）

Stage 00+01 仅记录方向，不编写正式工单状态机、接口、共享运行时代码或跨模块数据联动。此文档不构成已冻结的数据契约。

后续方向：AI随手拍、设备健康告警或预测预警提供工单来源信息，由负责人 A 维护的工单模块统一接收；来源模块由负责人 B 维护。来源模块不直接改工单页面或其内部状态。同模块 PC / 小程序共享最终确认的业务定义，页面独立实现。

以下事项均须 A / B 与业务方确认后，才能形成正式协议：

| 讨论项 | 待确认方向 |
| --- | --- |
| 来源与标识 | 来源类别、来源记录标识、关联设备和原始记录追溯；分类、字段名、必填性和编号规则尚未冻结 |
| 内容与证据 | 位置、问题描述、风险等级、图片/附件、上报人、发生/上报时间；权限、数据授权和附件保存方式待确认 |
| 接收边界 | 工单模块统一接收；人工确认点、重复提交处理、幂等、接收成功/失败反馈待确认 |
| 状态与责任 | 来源侧状态与工单侧状态如何关联、由谁维护、是否回传及何时回传待确认，不在本阶段列正式状态值 |
| PC / 移动端 | 字段口径、时间格式、枚举、权限和离线/失败处理的共用边界待确认 |
| 验证方式 | 后续在无真实服务时如何表示 Mock、如何证明接收与追溯，以及真实接口替换边界待确认 |

A 负责工单接收边界与协议整合，B 确认来源数据及其生命周期；任何正式协议变更需列出影响模块和两端兼容性。无本阶段运行时实现。
