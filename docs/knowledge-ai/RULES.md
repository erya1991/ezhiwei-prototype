## 状态与边界

- `web/src/data/knowledgeAiMock.js` 是三个菜单的唯一资料状态源。使用 Vue 响应式状态，并以 `ezhiwei:knowledge-ai:v1:state` 为键写入当前标签页的 SessionStorage；在存储可用且未被清理的条件下，仅保证当前标签页会话内刷新或热更新后恢复资料、版本、片段及审核记录。它不具备真正的跨会话持久化能力，不保证新标签、关闭会话或换浏览器后保留，也不提供跨标签实时同步或跨设备共享。不写 LocalStorage、不存服务器；角色、项目选择和聊天消息仍不持久化。原 `knowledgeBase.js` 未修改，8 条知识、6 位专家及分类均保留。
- 每份资料有稳定 ID、版本数组和唯一 `currentVersion`。最新维护版本与当前有效版本分别展示；已发布版不可直接加工或修改，修订生成下一草稿版。草稿保存会清除原加工结果，必须重新加工与校验；待审核版锁定编辑。
- 资料流程：草稿 → 待审核 → 已发布 → 已归档。退回为草稿，原因及审核记录保留；新版本发布前旧版有效，新版发布后只检索新版。归档使整份资料失效，版本正文及历史记录仍可查看。
- 加工独立维护：未加工 → 加工中 → 待校验 → 可检索；失败可重试。提交审核要求人工确认加工结果。可检索只是加工状态，未发布、历史版或归档版仍不能被新问答引用。
- 加工按换行及句末标点截取对应正文；知识要素仅按文本符号确定性标记，可人工校正分类、重选原文或补充正文摘录。确认时要求每段可在对应正文中逐字核对。补充新事实须先编辑正文，再重新加工。候选规则不写入生效规则。
- 附件仅登记名称和大小（≤20MB），没有上传、OCR、解析或下载能力。附件无正文时加工失败；不生成虚假知识。
- 演示资料维护人员可编辑、加工、校验、提交；专业审核人员可发布、退回、归档；只读访客不能执行这些操作。仅模拟职责，平台登录及鉴权未改动。初始种子的发布与校验状态明确标注为预置演示，并非真实审核。
- 资料类型为 V2 九类，专业系统为原有八类，两者独立。项目专属资料必须选择 Mock 项目 A/B。平台通用知识对演示角色可见；项目专属知识在匹配项目的维护/审核角色下可检索，只读访客仅可检索平台通用知识。
- 问答默认 Mock 模式：仅从已发布、可检索、当前有效且有权限的资料中，按专业、项目和关键词匹配。采用规范化文本的二字片段计分、稳定排序，最多返回 6 段；同分时交错取不同资料的片段，避免单份旧资料挤占所有名额。不是语义向量检索，仍可能命中宽泛的相关词。回答逐项摘录实际命中片段，不补写无来源事实；无命中明确显示“暂无有效知识依据”。
- 问答来源保存资料 ID、版本、片段 ID 和发送时的文本快照；点击打开对应版本。后续提问重新核验有效版本。“继续”等追问沿用此前问题关键词；切换项目、专业、角色或模式清空当前会话，防止混用上下文。离开问答页不保存对话。
- 原 DeepSeek 流式调用、非流式回退、超时、消息构造与格式化路径保留，独立模式明确标注真实服务；本轮未调用真实 AI。用户正文使用 Vue 文本插值，只有原仓库固定知识/专家种子 HTML 保持原有渲染。
